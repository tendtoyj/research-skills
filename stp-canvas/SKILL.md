# stp-canvas · 종합: STP + 비즈니스 모델 캔버스

종합 단계다. **새로 조사하지 않는다.** 프로젝트에 올라온 조사 파일을 서로 맞대어 "누구에게, 어떤 자리로, 어떻게 돈을 버는가"를 정한다. 결과는 전문가 검증봇이 검토하고, 최종 보고서(final-report)가 이어서 읽는다.

## 공통 규칙

- **맥락 파일**: 프로젝트 파일의 `healthcare-context.md`를 읽는다. 특히 2장(이용자·결정자·지불자)을 세분화와 캔버스에 반영한다.
- **근거 표시**: 모든 판단에 근거 파일을 괄호로 단다. 예: (트렌드 S2), (시장규모 SAM), (경쟁사 빈틈 1). 조사 파일에 근거가 없는 내용은 **"가정"**이라고 표시한다.
- **결과는 파일로**: 다운로드할 수 있는 파일로 만든다. 기본 `.md`, 사용자가 원하면 Word나 PDF. 파일명은 `strategy-brief.md`이다. 프로젝트 지시문에 파일명 규칙이 있으면 그 규칙을 따른다.
- **메모리**: 본문은 저장하지 않는다. `[STP 완료] 타겟 1줄 / 포지셔닝 문장`만 남긴다.
- **분량**: A4 3쪽 안쪽.

## 1. 입력 확인

프로젝트 파일에서 아래를 찾는다. 프로젝트 지시문에 파일명 규칙이 있으면 그 이름(예: 트렌드, 시장규모, 경쟁사)으로 찾는다. `-v2`(팩트체크 후 보완본)가 있으면 그것을 우선한다.

| 파일 | 없을 때 |
|---|---|
| 트렌드 (`market-trend.md`) | 사용자에게 알리고, 계속할지 묻는다 |
| 시장규모 (`market-size.md`) | 같음 |
| 경쟁사 (`competitive-intel.md`) | 같음 |
| 팩트체크 결과 (`fact-check.md`) | 없어도 진행. 있으면 ❌·❓ 항목은 근거로 쓰지 않는다 |

시작할 때 "읽은 파일 목록"을 사용자에게 먼저 보여 주고 빠진 게 있는지 확인받는다.

## 2. 세분화 (Segmentation)

시장을 2~4개 그룹으로 나눈다. 인구통계만으로 나누지 말고 헬스케어에서 의미 있는 기준을 쓴다.

- 질환 단계·관리 수준 (진단 직후 / 안정기 / 합병증 위험)
- 디지털 이용 능력
- 지불 능력과 지불 주체
- 의료 이용 행태 (병원 방문 주기, 건강정보를 어디서 찾나)

그룹마다 규모(시장규모 파일 근거)와 핵심 불편(트렌드·경쟁사 파일 근거)을 적는다.

## 3. 타겟팅 (Targeting)

그룹을 아래 기준으로 비교해 하나를 고른다. 상·중·하로 매기고 이유를 한 줄씩 단다.

| 기준 | 근거 파일 |
|---|---|
| 규모 | 시장규모 |
| 문제의 크기 | 트렌드, 경쟁사(이용자 반응) |
| 경쟁 강도 | 경쟁사 |
| 닿을 수 있는가 (채널, 지불자) | 경쟁사, 시장규모 |
| 규제 부담 | 트렌드 P, 맥락 파일 5장 |

## 4. 포지셔닝 (Positioning)

- **포지셔닝 맵**: 경쟁사 파일에서 고객이 중요하게 여기는 축 2개를 고른다. 경쟁사와 우리를 표로 배치한다(축1 낮음·높음 × 축2 낮음·높음).
- **포지셔닝 문장**: "[타겟]에게 [우리 서비스]는 [경쟁 대안]과 달리 [핵심 차별점]을 주는 [카테고리]다."
- 차별점이 경쟁사 파일의 "빈틈"과 연결되는지 확인한다.

## 5. 페르소나 1명

타겟 그룹을 대표하는 가상 인물 한 명을 만든다. 실존 인물이나 커뮤니티 글쓴이를 본뜨지 않는다.

- 이름 · 나이 · 상황 (한 줄)
- 목표
- 불편함 (근거 파일 표시)
- 의료 이용 행동 (언제 병원에 가나, 건강정보를 어디서 찾나, 지금 무엇을 대신 쓰나)

## 6. 비즈니스 모델 캔버스

9칸을 채운다. 헬스케어에서는 **고객(이용자)과 지불자를 나눠** 적는다.

| 칸 | 헬스케어에서 볼 것 |
|---|---|
| 고객 세그먼트 | 타겟 이용자 + (다르면) 결정자·지불자 |
| 가치 제안 | 포지셔닝 문장의 차별점 |
| 채널 | 앱스토어, 병원·약국, 보험사·기업, 커뮤니티 |
| 고객 관계 | 셀프 서비스, 코칭, 의료진 연결 |
| 수익원 | 누가, 무엇에, 얼마를 내나 (시장규모의 가격 가정과 맞춘다) |
| 핵심 자원 | 데이터, 의료 자문, 인허가, 기술 |
| 핵심 활동 | 서비스 운영, 의료진 협업, 인허가 대응 등 |
| 핵심 파트너 | 병원, 기기 제조사, 보험사, 약국 |
| 비용 구조 | 개발, 인허가·임상, 마케팅, 운영 |

## 8. 마무리

파일을 만든 뒤 알린다.

1. 파일 이름
2. "다운로드해서 프로젝트 파일에 올리고, 같은 파일을 전문가 검증봇에게 보내 검토받으세요."
3. 가정 목록 개수

## 업데이트 모드

사용자가 전문가 검토 의견을 주며 보완을 요청하면, 의견마다 반영 / 부분 반영 / 반영 안 함과 이유를 "전문가 검토 반영" 섹션에 표로 적고 본문을 고친다. 파일명을 `strategy-brief-v2.md`로 한다.

## 하지 않는 것

- 새로운 웹 조사 (근거가 부족하면 "가정"으로 표시하고 어떤 조사가 필요한지만 적는다)
- 최종 발표 자료 → final-report
