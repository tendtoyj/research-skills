# fact-check · 팩트체크

조사 파일과 종합 파일에 적힌 **숫자, 제도, 경쟁사 정보, 트렌드 서술이 정말 맞는지** 1차 출처로 확인한다. 쓴 사람과 따로, 의심하는 눈으로 본다. 판정만 하고 고치지는 않는다. 고치는 일은 각 스킬의 보완 모드가 한다.

## 공통 규칙

- **다른 눈으로**: 조사를 한 채팅이 아니라 **새 채팅**에서 부르는 것을 권한다. 이 대화에서 이미 조사한 내용이 있어도 그것을 근거로 삼지 않는다. 문서에 적힌 출처와 문장을 믿지 않고 원문에서 다시 찾는다.
- **참고 자료**: 작업 공간(대화 첨부, 프로젝트 파일, 지시문)에 맥락 파일이나 리서치 가이드가 있으면 먼저 읽는다. 그 안의 데이터 소스, 해석 시 주의점, 출처 규칙을 이 스킬의 기준보다 우선한다. 특히 그 분야에서 자주 틀리는 점 목록이 있으면 5단계에 그대로 넣는다.
- **1차 출처 우선**: 기관 원문, 공공 통계표, 논문, 공시, 회사 공식 페이지를 기사·블로그보다 먼저 본다. 문서에 붙은 링크는 **직접 열어** 그 숫자와 문장이 거기 있는지 확인한다. 검색 결과 요약만 보고 판정하지 않는다.
- **추측 금지**: 원문을 찾지 못하면 "확인 불가"로 둔다. 그럴듯하다고 "확인됨"으로 하지 않는다.
- **고치지 않기**: 원래 파일을 고쳐 쓰지 않는다. 고칠 내용은 "고쳐 쓸 문장"에만 적는다.
- **결과는 파일로**: 대화창 답변이 아니라 **다운로드할 수 있는 파일 두 개**를 처음부터 함께 만든다. 원본 `fact-check.md`와 보기용 `fact-check.html`(아래 "보기용 HTML"). 사용자가 원하면 Word나 PDF도 준다. 사용자가 정한 파일명 규칙이 있으면 그것을 따른다.
- **메모리**: 본문은 저장하지 않는다. `[팩트체크 완료] ✅N ⚠️N ❌N ❓N · 고칠 파일 목록`만 남긴다.
- **읽히는 문장으로 쓰기**: 결과(md와 html 모두)는 이 조사를 처음 보는 사람이 읽고 바로 이해할 수 있게 쓴다.
  - 항목마다 **무엇이 일어나고 있는지 → 근거 → 그래서 우리 주제에 무슨 뜻인지**를 완전한 문장("~다")으로 쓴다.
  - 단어, 화살표(→), 가운뎃점(·)만 이어 붙인 메모체로 쓰지 않는다. 화살표는 순서나 흐름을 보여 줄 때만 쓴다.
  - "한 줄"로 쓰라는 곳도 완전한 한 문장으로 쓴다. 표 칸에 다 못 쓰면 표 아래에 번호를 달아 문장으로 풀어 쓴다.
  - 줄임말과 전문 용어(TAM, SAM, SOM, CAGR, PEST 등)는 처음 나올 때 한 번 풀어 쓴다.
  - 예: (X) "외식 물가 상승 → 기회 · 곧" / (O) "외식 물가가 최근 3년 동안 약 11% 올랐다[통계청, 2025]. 점심값 부담이 커질수록 가격이 정해진 구독이 매력적으로 보일 수 있어, 우리 주제에는 1~3년 안에 기회가 된다."

## 모드

| 모드 | 언제 | 하는 일 |
|---|---|---|
| 전체 검증 | 처음 검증할 때 | 받은 파일 전체에서 주장을 뽑아 1~6단계 |
| 한 파일만 | 사용자가 파일 하나나 주제 하나를 집어 말할 때 | 그 파일·주제에서만 주장을 뽑는다 |
| 다시 검증 | `-v2` 같은 보완본과 이전 `fact-check.md`를 함께 받았을 때 | 이전에 ❌·⚠️·❓였던 주장이 고쳐졌는지만 다시 본다. 파일명을 `fact-check-v2.md`로 한다 |

## 1. 입력 확인

작업 공간에서 검증할 파일을 찾아 목록을 보여 주고 확인받는다. `-v2`가 있으면 그것을 우선한다.

| 파일 | 주로 볼 것 |
|---|---|
| 시장 스캔 (`market-landscape.md`) | 규모 숫자, Bottom-up 각 단의 값, 성장률, 제도·규제 항목 |
| 경쟁사 (`competitive-intel.md`) | 가격, 인허가·인증, 투자·이용자 수 같은 규모 신호, 대표 문구 |
| 소셜 리스닝 (`customer-voice.md`) | 출처 링크가 실제로 있는지, 빈도 표현이 과장되지 않았는지 |
| STP (`stp.md`) | 근거로 인용한 숫자와 사실이 조사 파일·원문과 같은지 |
| 비즈니스 캔버스 (`business-canvas.md`) | 가격, 비용, 파트너 정보 |

파일이 하나도 없으면 멈추고, 검증할 파일을 첨부하거나 프로젝트 파일에 올려 달라고 한다.

## 조사 깊이

| 깊이 | 뽑는 주장 | 주장당 원문 열람 |
|---|---|---|
| 가볍게 | 최대 8개 | 1건 |
| 보통 | 최대 15개 | 1~2건 |
| 깊게 | 최대 25개 | 2건 이상, 출처끼리 교차 확인 |

기본은 보통. "빠르게"는 가볍게, "꼼꼼히"는 깊게로 본다.

## 2. 주장 뽑기

검증할 주장을 우선순위대로 뽑는다.

1. **숫자**: 시장 규모, 인구, 비율, 성장률, 가격
2. **제도·규제**: 법, 인허가, 지원 사업, 시행일
3. **경쟁사 정보**: 가격, 인증, 투자, 이용자 수, 출시·철수
4. **트렌드 서술**: "늘고 있다", "처음이다", "가장 크다" 같은 단정

주장마다 **위치**(파일 이름과 항목 번호, 예: market-landscape P2, stp 포지셔닝)를 적는다. 같은 숫자가 여러 파일에 나오면 하나로 묶고 위치를 모두 적는다. 뽑은 목록을 먼저 보여 주고 진행한다.

## 3. 원문 확인

주장마다 웹 검색과 원문 열람으로 1차 출처를 찾는다.

- 문서에 링크가 있으면 먼저 그 링크를 연다. 링크가 열리지 않거나 그 숫자가 없으면 그 사실을 적는다.
- 링크가 없거나 2차 자료면 1차 출처를 새로 찾는다.
- 확인한 출처의 이름, 데이터 연도, 링크, 확인일을 적는다.

## 4. 판정

| 판정 | 기준 |
|---|---|
| ✅ 확인됨 | 원문에서 같은 숫자·내용을 확인했다 |
| ⚠️ 부분 일치 | 원문은 있지만 기준연도, 대상(모집단), 단위, 정의 중 하나 이상이 다르다 |
| ❌ 틀림 | 원문과 다르거나, 붙은 출처에 그 내용이 없거나, 출처가 존재하지 않는다 |
| ❓ 확인 불가 | 원문을 찾지 못했다 |

⚠️·❌에는 **무엇이 다른지**와 **고쳐 쓸 문장**(출처 포함)을 함께 적는다. ❓에는 어디까지 찾아봤는지 적는다.

## 5. 자주 틀리는 점 점검

주장 하나하나와 별개로, 문서 전체에서 아래를 점검해 통과 / 문제 있음으로 적는다. 문제가 있으면 위치를 단다.

- 기준연도, 대상, 단위, 정의가 다른 숫자를 한 계산이나 비교에 섞었나
- 조사 추정치와 실제 이용·거래 기록처럼 성격이 다른 숫자를 섞었나
- 해외 숫자를 국내에 그대로 썼나
- 3년 넘은 자료를 최신처럼 썼나
- 관심(검색량, 게시글 수)을 수요나 구매로 바꿔 썼나
- 효과나 인과를 단정하거나 부풀렸나
- 참고 자료에 있는 그 분야의 함정 목록

## 6. 고칠 파일 정하기

파일마다 ❌·⚠️·❓ 개수를 세고, 무엇을 어떤 순서로 고칠지 정한다.

- **조사 파일을 먼저** 고친다. 종합 파일(STP, 캔버스)은 조사 파일에서 나오므로, 조사 파일을 고친 뒤 보완한다.
- ❌가 있는 파일은 보완한다. ⚠️·❓만 있는 파일은 사용자가 고를 수 있게 "선택"으로 표시한다.
- 파일마다 부를 명령을 적는다. 예: `/market-scanner 팩트체크 결과 반영해서 보완해 줘` (+ `fact-check.md` 첨부)
- 마지막에 **가장 먼저 고칠 3가지**를 고른다. 결론을 가장 크게 바꾸는 것(규모 숫자, 타겟·포지셔닝의 근거)부터.

## 보기용 HTML

md와 같은 내용을 **도식으로 바꿔** 한눈에 보이게 한 `fact-check.html`을 처음부터 함께 만든다. md의 표를 HTML 표로 옮기는 것이 아니다.

- **md가 원본**: 보완 단계에는 md를 쓴다. HTML에만 있는 내용을 넣지 않고, md를 고치면 HTML도 고친다. 다시 검증하면 둘 다 `-v2`로 만든다.
- **표는 맨 아래에만**: 위쪽 도식 부분에는 `<table>`을 쓰지 않는다. 도식은 CSS 격자(grid·flex)와 인라인 SVG로 그린다. 표는 맨 아래 "자세히 보기"(`<details>`로 접어 둠)에만 둔다.
- **파일 하나로 완결**: CSS는 `<style>` 안에 넣는다. 외부 스크립트·웹 폰트·이미지 링크를 쓰지 않는다. 흰 배경, 본문 최대 너비 960px, 휴대폰에서는 여러 열 도식을 1열로 접는다. A4로 인쇄해도 잘리지 않게 한다.
- **판정 색은 고정**: ✅ 초록 `#2e7d4f`, ⚠️ 주황 `#c8702a`, ❌ 빨강 `#c0392b`, ❓ 회색 `#8a8f98`. 모든 도식에서 같은 색을 쓴다.
- **참고 자료**에 시각화 기준이 있으면 그것을 따른다.

**이 화면의 질문**: 무엇이 틀렸고, 어느 파일부터 고쳐야 하나?

**도식** (위에서 아래 순서)

1. **판정 막대** (md "한눈에 보기"): 가로로 긴 막대 하나를 ✅⚠️❌❓ 개수만큼 판정 색으로 나눠 칠한다. 칸 안에 개수. 막대 아래에 "가장 큰 문제" 한 줄을 빨간 테두리 상자로.
2. **파일별 판정 띠** (md "검증표"의 위치): 파일마다 가로 줄 하나. 줄 왼쪽에 파일 이름, 오른쪽에 그 파일의 주장을 판정 색 동그라미로 늘어놓는다(동그라미 안에 주장 번호). 주장이 하나도 없는 파일은 "검증할 주장 없음".
3. **틀린 곳 카드** (md "검증표"의 ❌·⚠️): ❌ 먼저, 그다음 ⚠️. 카드마다 위에 판정 배지와 위치, 가운데 "문서에 적힌 것"(줄 그은 글씨) → "원문"(굵은 글씨) 두 줄, 아래에 무엇이 다른가 한 줄과 출처 배지. ❓는 회색 작은 카드로 따로 모은다.
4. **자주 틀리는 점 신호등** (md "자주 틀리는 점 점검"): 점검 항목마다 줄 하나, 왼쪽에 초록(통과) 또는 빨강(문제 있음) 동그라미, 오른쪽에 위치 배지.
5. **고칠 순서 흐름** (md "고칠 파일"): 왼쪽에서 오른쪽으로 화살표로 이은 파일 칸. 조사 파일 칸 → 종합 파일 칸 순서. 칸마다 파일 이름, ❌·⚠️ 개수 배지, 필수(진한 테두리) / 선택(점선) / 없음(회색), 그 아래 부를 명령을 코드 글씨로.
6. **가장 먼저 고칠 3가지**: 번호가 크게 붙은 카드 3장 가로 배열.

**자세히 보기 (표)**: 검증표 전체, 자주 틀리는 점 점검 표, 조사 기록.

**가장 강조할 것**: ❌ 틀린 곳과, 그것을 고칠 첫 번째 명령.

**조심할 것**
- ✅ 확인된 주장을 화면 위쪽에 늘어놓지 않는다. 개수와 판정 띠의 초록 동그라미로만 보여 준다.
- 판정 색을 다른 뜻으로 쓰지 않는다.

## 마무리

파일을 만든 뒤 알린다.

1. 파일 이름 두 개: `fact-check.md`(원본, 보완할 때 첨부하는 파일)와 `fact-check.html`(보기용)
2. 요약 한 줄 ✅N · ⚠️N · ❌N · ❓N 과 가장 큰 문제 1개
3. 고칠 순서와 부를 명령. "조사 파일을 먼저 보완하고, 그다음 STP·캔버스를 보완하세요."
4. "`fact-check.md`를 프로젝트 파일에 올려 두세요. 이후 스킬이 이 판정을 보고 틀린 내용을 근거로 쓰지 않습니다."

## 품질 체크리스트

- [ ] 메모체(단어·화살표만 이은 줄) 없이 완전한 문장으로 썼고, 항목마다 "그래서 무슨 뜻인지"가 있다
- [ ] md와 html을 둘 다 만들었고, 두 파일의 내용이 같다
- [ ] html 위쪽에 표가 없고, "보기용 HTML"에 정한 도식이 모두 그려졌다
- [ ] 주장마다 위치(파일과 항목)가 있다
- [ ] 판정마다 직접 연 원문 출처가 있다. 검색 요약만 보고 판정한 것이 없다
- [ ] 원문을 못 찾은 것은 ❓로 두었다
- [ ] ⚠️·❌에 무엇이 다른지와 고쳐 쓸 문장이 있다
- [ ] 자주 틀리는 점을 따로 점검했다
- [ ] 고칠 파일 표가 조사 파일 → 종합 파일 순서다
- [ ] 원래 파일을 고쳐 쓰지 않았다
- [ ] 참고 자료가 있었다면 그 기준을 지켰다

## 예시 (일부)

> **요약**: 시장 스캔, 소셜 리스닝, STP 세 파일에서 주장 12개를 확인했다. 7개는 원문과 같았고(✅), 3개는 기준이 조금 달랐고(⚠️), 1개는 틀렸고(❌), 1개는 원문을 찾지 못했다(❓).
>
> **❌ 틀림**: 시장 스캔(E1)과 STP 교차 분석은 "외식 물가가 3년간 15% 올랐다"고 썼다. 통계청 원문을 확인하니 약 11%였다. "외식 물가가 3년간 약 11% 올랐다[통계청, 2025]"로 고쳐야 한다.
>
> **⚠️ 부분 일치**: "수도권 사무직 420만 명"(시장 스캔 Bottom-up 1단)은 2022년 기준 숫자다. 더 최신 통계표가 있으므로 바꾸는 것이 좋다.
>
> **고칠 순서**: 틀린 숫자가 있는 시장 스캔을 먼저 보완하고(`/market-scanner 팩트체크 결과 반영해서 보완해 줘`), 그 숫자를 근거로 쓴 STP를 그다음에 보완한다(`/stp 팩트체크 결과 반영해서 보완해 줘`). 소셜 리스닝은 고칠 것이 없다.

## 하지 않는 것

- 원래 파일 고쳐 쓰기 → 각 스킬의 보완 모드
- 새로운 조사로 빈칸 채우기 → `market-scanner`, `competitor-analysis`, `customer-voice`
- 전략이 좋은지 판단하기 (사실이 맞는지만 본다)
