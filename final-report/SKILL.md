# final-report · 최종 보고서 (PPT)

마지막 단계다. 지금까지 만든 시장조사 파일을 모아 발표용 PPT 한 벌로 정리한다. **새로 조사하지 않고**, 파일에 있는 내용과 출처만 쓴다.

## 공통 규칙

- **맥락 파일**: 프로젝트 파일의 `healthcare-context.md`를 읽는다. 특히 5장(의료광고·과장 표현 금지)을 슬라이드 문구에 적용한다.
- **근거**: 슬라이드의 수치와 주장은 조사 파일에 있는 것만 쓴다. 출처는 마지막 출처 슬라이드에 모으고, 본문에는 짧게 [자료명, 연도]만 단다.
- **팩트체크 결과 존중**: 팩트체크에서 ❌ 판정을 받은 내용은 쓰지 않는다. ⚠️·❓는 "확인 필요"를 달고 쓰거나 뺀다.
- **결과**: PPT 파일로 만든다. 사용자가 원하면 Word 보고서도 함께 만든다. 파일명은 `final-report`이다. 프로젝트 지시문에 파일명 규칙이 있으면 그 규칙을 따른다.
- **메모리**: `[최종보고서 완료] 슬라이드 N장`만 남긴다.

## 1. 입력 확인

프로젝트 파일에서 아래를 찾아 **읽은 파일 목록**을 먼저 보여 준다. 프로젝트 지시문에 파일명 규칙이 있으면 그 이름으로 찾는다. `-v2`가 있으면 그것을 우선한다.

- `market-trend.md`, `market-size.md`, `competitive-intel.md` (`-v2` 우선)
- 팩트체크 결과 (`fact-check.md`)
- `strategy-brief.md` (`-v2` 우선)
- 전문가 검토 의견 (`expert-review-...`, 있으면)

빠진 파일이 있으면 알리고, 그래도 진행할지 묻는다.

## 2. 목차 먼저 확인받기

바로 PPT를 만들지 않는다. 아래 기본 목차에 슬라이드별 핵심 메시지(한 문장)를 채워 먼저 보여 주고, 사용자가 확인하면 만든다. 기본 10장, 사용자가 장수를 정하면 따른다.

| # | 슬라이드 | 핵심 메시지에 들어갈 것 | 근거 파일 |
|---|---|---|---|
| 1 | 표지 | 주제, 작성자(사용자가 알려 주면) | |
| 2 | 문제 정의 | 누가, 어떤 상황에서, 무엇이 불편한가 | 전략 브리프 페르소나 |
| 3 | 시장 동향 | PEST 중 우리 주제에 가장 중요한 3가지 | 트렌드 |
| 4 | 시장 규모 | TAM·SAM·SOM과 계산식, 가장 민감한 가정 | 시장규모 |
| 5 | 경쟁 지도 | 직접·간접·대체재와 빈틈 | 경쟁사 |
| 6 | 타겟과 포지셔닝 | 선택한 타겟, 포지셔닝 문장, 포지셔닝 맵 | 전략 브리프 |
| 7 | 비즈니스 모델 | 캔버스 핵심 (가치 제안, 고객·지불자, 수익원) | 전략 브리프 |
| 8 | 검증 과정 | 팩트체크에서 고친 것, 전문가 검토에서 반영한 것 | 팩트체크, 전문가 검토 |
| 9 | 남은 질문 | 아직 확인하지 못한 것과 확인 방법 (인터뷰, 원문, 전문가) | 모든 파일의 확인 필요·가정 목록 |
| 10 | 출처 | 번호순 출처 목록 | 모든 파일 |

슬라이드 제목은 주제어가 아니라 **메시지 문장**으로 쓴다. 예: "시장 규모" 대신 "스마트폰으로 혈당을 기록하는 환자만 약 OO만 명이다".

## 3. PPT 만들기

- 한 슬라이드에 메시지 하나. 글은 3~5줄, 가능한 표나 도식으로.
- 수치에는 단위, 기준연도, 추정 여부를 붙인다.
- 8번 "검증 과정"은 빼지 않는다. 무엇을 틀렸고 어떻게 고쳤는지가 리서치의 신뢰도를 보여 준다.
- 효과를 단정하는 표현("치료한다", "완치", "100%")은 쓰지 않는다.

## 4. 마무리

PPT를 만든 뒤 알린다.

1. 파일 이름과 내려받는 방법 (슬라이드 카드의 내보내기)
2. "확인 필요"가 붙은 슬라이드 번호
3. 제출 전에 직접 확인할 것: 출처 링크가 열리는지, 숫자가 원 파일과 같은지

## 하지 않는 것

- 새로운 조사, 새로운 수치 추가
- 팩트체크에서 틀린 것으로 판정된 내용 사용
