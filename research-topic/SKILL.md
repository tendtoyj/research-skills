# research-topic · 리서치 주제 찾기

## 목적

본격적인 조사 전에 **조사해 볼 만한 거리**를 찾고 하나로 정한다. 관심 있는 영역은 있지만 무엇을 조사할지 모를 때 쓴다. 아이디어를 짜내는 스킬이 아니다. 그 영역에서 **지금 무엇이 바뀌고 있고, 그래서 무엇을 확인해 볼 만한지**를 찾아 리서치 질문으로 만든다.

결과는 아래 두 줄이다.

```
리서치 대상 주제 정의: [누가] [어떤 상황에서] [어떤 불편]을 겪는가
리서치 대상 시장 정의: [어떤 범위의] [어떤 서비스·제품] 시장
```

시장 정의 예: "2030 OO 초기 관리 시장", "병원 치료 전 단계의 자가 관리 서비스 시장".

이 두 줄은 프로젝트 메모리에 저장되고, 이후 조사 스킬이 다시 묻지 않고 그대로 쓴다.

## 공통 규칙

- **참고 자료**: 작업 공간(대화 첨부, 프로젝트 파일, 지시문)에 맥락 파일이나 리서치 가이드가 있으면 먼저 읽는다. 그 안의 데이터 소스, 분야의 범위, 주의점을 변화 신호를 찾을 때와 후보를 고를 때 반영한다.
- **고르는 건 사용자**: AI는 후보와 근거를 보여 주고, 고르는 것은 사용자가 한다.
- **한 번에 한 질문**: 질문을 여러 개 쌓지 않는다. 양식을 한꺼번에 던지지 않는다. 사용자가 말한 것을 짧게 되짚어 확인한 뒤 넘어간다.
- **가볍게**: 5~10분 안에 끝낸다. 웹 검색은 변화 신호를 찾는 데 2~3회만 쓴다. 깊은 조사는 다음 스킬이 한다.
- **출처**: 변화 신호에는 출처 이름과 연도, 링크를 단다. 원문을 열어 보지 못한 것은 "확인 필요"를 붙인다.
- **메모리**: 확인받은 두 줄만 저장한다. 후보 목록과 대화 내용은 저장하지 않는다.
- **언어**: 사용자의 언어로 쓴다. 지정이 없으면 한국어.

## 모드

| 모드 | 언제 | 하는 일 |
|---|---|---|
| 새로 찾기 | 메모리에 주제 정의가 없을 때 | 1~6단계 |
| 다시 찾기 | 메모리에 이미 주제 정의가 있을 때 | 지금 저장된 두 줄을 보여 주고, 바꿀지 다듬을지 먼저 묻는다. 다듬기면 5~6단계만 한다 |

## 절차

### 1단계 · 출발점

관심 있는 **영역**을 한 줄로 받는다. 무엇이든 출발점이 될 수 있다.

| 출발점 | 예 |
|---|---|
| 분야 | "식생활", "운동", "반려동물" |
| 대상 | "1인 가구 직장인", "대학 신입생" |
| 기술·제도 | "AI 챗봇", "새로 바뀐 제도" |
| 막연한 아이디어 | "점심 구독 같은 거" |
| 내가 겪은 불편 | "매일 점심 메뉴 고르기가 피곤함" |

아무것도 떠오르지 않는다고 하면, 참고 자료의 분야 안에서 예시 영역 3~4개를 보여 주고 고르게 한다.

### 2단계 · 변화 신호 훑기

그 영역에서 **최근 1~3년 사이에 바뀌고 있는 것**을 웹 검색 2~3회로 찾는다. 참고 자료에 추천 데이터 소스가 있으면 그것부터 본다.

| 신호 | 볼 것 |
|---|---|
| 제도·규제 | 새로 생기거나 바뀐 규칙, 지원 사업 |
| 기술 | 새로 퍼지고 있는 기술, 싸지거나 쉬워진 것 |
| 행동·인식 | 사람들의 생활 방식, 소비, 정보 찾는 방식의 변화 |
| 시장 | 새 서비스, 투자, 철수, 가격 변화 |

신호 4~6개를 한 줄씩, 출처와 함께 보여 준다. 사용자가 이미 아는 신호가 있으면 함께 넣는다.

### 3단계 · 조사 후보 3~5개

변화 신호에서 **리서치 질문**을 뽑는다. 질문은 "~가 늘고 있나?", "~때문에 ~를 겪는 사람이 있나?", "~는 왜 아직 안 풀렸나?"처럼 조사로 확인할 수 있는 모양으로 쓴다. 해결책을 정해 두지 않는다.

후보마다 적는다.

| 후보 | 리서치 질문 | 왜 지금인가 (변화 신호) | 누가, 어떤 불편을 겪을 것 같은가 | 확인할 수 있는 자료 |
|---|---|---|---|---|
| A | | | | |

### 4단계 · 조사 가치 보기

후보를 아래 기준으로 상·중·하로 매겨 표로 보여 준다. 매긴 이유를 한 줄씩 단다.

| 기준 | 보는 것 |
|---|---|
| 변화가 있나 | 지금 볼 이유가 있나. 신호가 뚜렷한가 |
| 근거를 찾을 수 있나 | 통계, 보고서, 리뷰, 커뮤니티 같은 자료가 있을 것 같은가 |
| 시장이 될 수 있나 | 이 불편에 돈을 낼 사람(이용자든 다른 지불자든)이 있을 것 같은가 |
| 범위가 적당한가 | 너무 넓어 끝이 없거나, 너무 좁아 자료가 없지 않은가 |

AI가 하나를 추천할 수는 있지만 이유를 붙이고, 고르는 것은 사용자에게 맡긴다. 마음에 드는 게 없으면 2단계로 돌아가 다른 신호를 본다. 후보를 섞고 싶다고 하면 섞는다.

### 5단계 · 좁히기

고른 후보를 두 줄로 만든다. 한 번에 한 칸씩.

- **누가**: 넓은 집단을 좁힌다. "직장인" → "출근일이 들쭉날쭉한 30대 1인 가구 직장인"
- **어떤 상황에서**: 불편이 생기는 구체적인 순간. "점심시간마다" → "사무실에 출근한 날 점심을 정할 때"
- **어떤 불편**: 해결책이 아니라 불편으로 쓴다. "유연한 도시락 구독이 없다" (X) → "고정 배송이 출근일과 맞지 않아 음식이 남고, 매일 메뉴를 고르는 게 피곤하다" (O)
- **시장 정의**: "[어떤 범위의] [어떤 서비스·제품] 시장" + 들어가는 것 한 줄, 들어가지 않는 것 한 줄. 지역은 기본 국내.

### 6단계 · 확인하고 저장

두 줄을 보여 주고 확인받는다.

```
리서치 대상 주제 정의: 
리서치 대상 시장 정의: 
```

사용자가 확인하면 프로젝트 메모리에 이 두 줄을 저장한다. 메모리에 이전 주제가 있으면 바꿔도 되는지 먼저 묻고, 바꾸면 이전 것은 지운다.

저장한 뒤 4단계 표에서 이 후보의 가장 약한 기준을 짚어 먼저 할 조사를 한 줄로 안내한다.

| 가장 불안한 것 | 먼저 할 조사 |
|---|---|
| 시장이 있긴 한가, 얼마나 큰가 / 변화가 정말 있나 | `/market-scanner` |
| 이미 누가 하고 있지 않나 | `/competitor-analysis` |
| 사람들이 정말 이 불편을 겪나 | `/customer-voice` |

참고 자료에 조사 순서가 정해져 있으면 그것을 따른다.

## 품질 체크리스트

- [ ] 후보가 리서치 질문 모양이고, 해결책을 정해 두지 않았다
- [ ] 후보마다 변화 신호와 출처가 있다
- [ ] 조사 가치 표가 있고, 매긴 이유가 있다
- [ ] 주제 정의에 누가, 어떤 상황에서, 어떤 불편이 모두 있다
- [ ] 시장 정의에 들어가는 것과 안 들어가는 것이 있다
- [ ] 사용자가 직접 골랐고, 두 줄을 확인받았다
- [ ] 메모리에 두 줄만 저장했다

## 예시 (줄임)

> 출발점: "직장인 식생활"
> 변화 신호: 외식 물가 상승 [통계청, 2025] · 출근·재택 혼합 근무 정착 [고용 조사, 2025] · 도시락 정기 배송 서비스 늘어남 [기사, 2026]
> 후보 A: 혼합 근무 직장인은 고정 정기 배송 때문에 구독을 그만두고 있나? (변화 상 · 근거 중 · 시장 중 · 범위 상)
> 후보 B: 점심값 부담 때문에 점심을 거르는 직장인이 늘고 있나? (변화 상 · 근거 상 · 시장 하 · 범위 중)
> 고른 것: A
> 리서치 대상 주제 정의: 출근일이 들쭉날쭉한 30대 1인 가구 직장인이, 사무실에 출근한 날 점심을 정할 때, 고정 배송이 출근일과 맞지 않고 메뉴 고르기가 피곤하다
> 리서치 대상 시장 정의: 수도권 사무실 직장인 대상 점심 식사 정기 구독 시장 (도시락·샐러드 정기 배송 포함, 배달앱 단건 주문·구내식당 제외)
> 먼저 할 조사: "이미 누가 하고 있지 않나"가 가장 불안 → `/competitor-analysis`

## 하지 않는 것

- 본격적인 시장 조사 → `market-scanner`, `competitor-analysis`, `customer-voice`
- 해결책이나 서비스 기능 정하기 → 조사를 마친 뒤 `stp`, `business-canvas`
- 결과 파일 만들기. 사용자가 원할 때만 두 줄과 후보 표를 `research-topic.md`(원본)와 `research-topic.html`(보기용, 변화 신호 카드 · 조사 가치표 상·중·하 색 · 정한 두 줄 강조) 두 파일로 함께 준다. HTML은 파일 하나로 완결하고(외부 스크립트·폰트·이미지 없음) 흰 배경, 남색 `#2f4b7c` 강조색 하나로 만든다
