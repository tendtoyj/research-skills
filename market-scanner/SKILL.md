# market-scanner · 시장 스캔 (동향 + 규모)

주제가 속한 시장이 **어떤 흐름 속에 있고(PEST), 얼마나 큰지(TAM·SAM·SOM)** 조사한다. 규모는 숫자 하나보다 **어떻게 계산했는지**를 남기는 것이 목표다. 결과 파일은 다른 조사와 종합 단계가 공통으로 읽는 바탕이 된다.

## 공통 규칙

- **참고 자료**: 작업 공간(대화 첨부, 프로젝트 파일, 지시문)에 맥락 파일이나 리서치 가이드가 있으면 먼저 읽는다. 그 안의 용어 정의, 데이터 소스, 해석 시 주의점, 체크리스트를 이 스킬의 기준보다 우선한다.
- **출처**: 모든 수치와 주장에 [기관명, 자료명, 데이터 연도, 링크]를 붙인다. 검색 결과 요약만 보고 쓰지 않고 원문을 열어 수치가 거기 있는지 확인한다. 찾지 못하면 "확인 필요"라고 쓰고 추측으로 채우지 않는다.
- **최신성**: 검색어에 연도를 넣는다. 3년 넘은 자료는 쓰지 않거나 "(YYYY년 기준)"을 붙인다. 제도·규제는 시행일과 최신 개정 여부를 확인한다.
- **결과는 파일로**: 대화창 답변이 아니라 **다운로드할 수 있는 파일 두 개**를 처음부터 함께 만든다. 원본 `market-landscape.md`와 보기용 `market-landscape.html`(아래 "보기용 HTML"). 사용자가 원하면 Word나 PDF도 준다. 사용자가 정한 파일명 규칙이 있으면 그것을 따른다.
- **메모리**: 본문은 저장하지 않는다. `[시장 스캔 완료] TAM / SAM / SOM · 가장 큰 기회 1줄`만 남긴다.
- **분량**: A4 3~4쪽 안쪽. 표를 우선 쓰고 문장은 짧게.

## 모드

| 모드 | 언제 | 하는 일 |
|---|---|---|
| 새로 조사 | `market-landscape.md`가 없을 때 | 1~6단계를 처음부터 한다 |
| 보완 | 이전 파일이나 검토 결과(팩트체크, 전문가 의견)를 받았을 때 | 처음부터 다시 쓰지 않고 바뀐 항목만 고친다. 규모 값이 바뀌면 계산을 다시 돌린다. 파일명을 `market-landscape-v2.md`로 하고 맨 아래에 "수정 내역" 표(항목, 바꾸기 전, 바꾼 후, 근거)를 붙인다 |

## 먼저 읽을 것

시작하기 전에 작업 공간의 조사 파일을 모두 읽는다(`competitive-intel.md`, `customer-voice.md` 등).

- 이미 조사된 내용은 다시 조사하지 않고 이어서 본다.
- 다른 파일과 시장 정의가 다르면 사용자에게 알리고 어느 쪽으로 맞출지 묻는다.
- `market-landscape.md`가 이미 있으면 보완 모드를 제안한다.

## 1. 입력 확인

아래가 대화, 지시문, 메모리에 없으면 한 번에 묻는다. 이미 있으면 확인만 하고 넘어간다. 주제 정의가 아예 없으면 `/research-topic`으로 먼저 정하자고 안내한다.

| 항목 | 필수 | 설명 |
|---|---|---|
| 리서치 주제 정의 | 예 | [누가] [어떤 상황에서] [어떤 불편]을 겪는가 |
| 리서치 시장 정의 | 예 | 없으면 2단계에서 같이 정한다 |
| 서비스 형태와 가격 가정 | 아니요 | 모르면 "월 구독 / 1회 구매 / 기업·기관 판매" 중 하나를 가정하고 "가정"으로 표시한다 |
| 지역 범위 | 아니요 | 기본은 국내. 해외 비교가 필요하면 국가를 받는다 |
| 이미 아는 자료 | 아니요 | 사용자가 가진 기사, 보고서, 링크 |
| 조사 깊이 | 아니요 | 가볍게 / 보통 / 깊게 (기본: 보통) |

## 조사 깊이

| 깊이 | 단계당 웹 검색 | 원문 열람 | PEST 칸당 항목 | 규모 리포트 비교 | 시장 구조 축 |
|---|---|---|---|---|---|
| 가볍게 | 1~2회 | 0~1건 | 1~2개 | 1개 | 2개 |
| 보통 | 3~4회 | 2~3건 | 2~3개 | 2개 | 3개 |
| 깊게 | 5~6회 | 4~6건 | 3개 | 3개 이상 | 4개 |

"빠르게", "간단히"는 가볍게, "자세히", "제대로"는 깊게로 본다.

## 2. 시장 정의

조사를 시작하기 전에 시장을 좁게 정의한다. 넓은 업종("교육", "푸드")이 아니라 "수도권 사무실 직장인 대상 점심 식사 정기 구독 시장"처럼 쓴다.

- 시장 이름과 범위
- **경계**: 들어가는 것과 들어가지 않는 것
- **인접 시장**: 일부 겹치는 시장 (간접 경쟁사가 나오는 곳)
- 이용자 / 결정자 / 지불자가 각각 누구인지 (쓰는 사람, 도입을 결정하는 사람, 돈을 내는 사람)
- 참고 자료에 시장을 나누는 기준(예: 규제 대상인지 아닌지)이 있으면 여기서 판단하고, 애매하면 "경계, 확인 필요"

## 3. 시장 동향 (PEST)

웹 검색으로 자료를 찾는다. 찾는 순서는 검색엔진 → 공공 통계·기관 자료 → 전문·학술 자료다. 커뮤니티 반응은 사회(S) 항목의 가설로만 쓴다. 참고 자료에 추천 데이터 소스가 있으면 그것부터 본다.

| 칸 | 볼 것 |
|---|---|
| P 정치·법 | 규제, 인허가, 제도 변화, 개인정보 규제, 광고 규제, 정부 지원 사업 |
| E 경제 | 소비 여력, 가격과 지불 의향, 지불 주체, 투자 흐름, 비용 구조 |
| S 사회 | 인구 변화, 생활 방식, 인식과 정보 이용 행태, 접근성 |
| T 기술 | 새 기술, 확산 속도, 데이터 연동, 대체 기술 |

항목마다 다음을 적는다.

- 무엇이 일어나고 있나 (한두 문장)
- 우리 주제에 **기회**인가 **위협**인가
- 시점: 지금(0~1년) / 곧(1~3년) / 장기(3~5년)
- 근거: 수치나 사례 + 출처

## 4. 시장 규모 (TAM / SAM / SOM)

### 정의부터 맞추기

| 단계 | 뜻 | 예 |
|---|---|---|
| TAM 전체 시장 | 이 문제를 가진 사람 전체가 쓸 수 있는 시장 | 수도권 사무직 직장인 전체의 점심 식비 |
| SAM 유효 시장 | 우리 서비스 형태로 실제 닿을 수 있는 시장 | 그중 정기 배송을 받을 수 있는 사무실 밀집 지역 직장인 |
| SOM 수익 시장 | 3년 안에 현실적으로 가져올 수 있는 몫 | SAM 중 초기 채널로 확보 가능한 비율 |

지불자가 이용자와 다르면(회사, 기관, 보험, 부모가 돈을 냄) **누구 기준으로 셀지** 먼저 정한다. 이용자 수 기준 시장과 지불자 매출 기준 시장을 섞지 않는다.

### 위에서 아래로 (Top-down)

리포트에 나온 시장 규모에서 출발해 좁혀 간다.

- 시장 규모 리포트를 깊이에 맞게 찾는다. 기관마다 시장 정의가 다르니 **범위**로 적는다. 자료가 서로 다르면 차이와 이유를 쓴다.
- 각 리포트의 시장 정의, 데이터 연도, 성장률(CAGR)과 기간을 함께 적는다.

### 아래에서 위로 (Bottom-up)

사람 수 × 비율 × 가격으로 직접 계산한다. 계산 과정이 드러나서 검증하기 쉬우므로 이쪽을 더 중요하게 본다.

```
대상 인구 (공공 통계)
× 문제를 겪는 비율 (조사·통계)
× 서비스로 닿을 수 있는 비율 (이용률, 지역, 채널)
× 1인당 연간 지출 (가격 가정)
= 시장 규모
```

- 단계마다 숫자, 출처, 데이터 연도를 적는다.
- **조사 추정치와 실제 이용·거래 기록**처럼 성격이 다른 숫자를 섞지 않는다. 어느 쪽을 썼는지 적는다. 참고 자료에 이런 구분이 있으면 그 기준을 따른다.
- 출처 없이 넣은 비율은 "가정"으로 표시한다.
- 인구·지역 분모는 공공 통계표에서 직접 다시 확인해 보라고 사용자에게 안내한다.

### 시나리오

핵심 가정(닿는 비율, 가격)을 바꿔 보수 / 기준 / 낙관 세 값을 낸다. 어느 가정이 결과를 가장 크게 바꾸는지 한 줄로 적는다.

## 5. 시장 구조와 수요 주기

시장이 어떻게 나뉘어 있는지 깊이에 맞는 축 수만큼 본다.

- 가격대: 저가 / 중간 / 고가
- 채널: 온라인 직접 판매, 앱 마켓, 오프라인, 기업·기관 판매 등
- 고객군: 누가 사나 (상황, 개인·기업)
- 하위 카테고리: 주요 제품·서비스 종류

수요 주기도 본다. 많이 찾는 때와 적게 찾는 때, 행사·제도 일정에 따른 변화. 뚜렷한 주기가 없으면 "뚜렷한 주기 없음"이라고 쓴다.

## 6. 시사점

동향과 규모를 함께 놓고 우리 주제에 중요한 시사점 3개를 뽑는다. 각 시사점에 근거가 된 항목 번호(PEST 번호, 규모 표)를 단다.

## 보기용 HTML

md와 **같은 내용**을 한눈에 보이게 정리한 `market-landscape.html`을 처음부터 함께 만든다.

- **md가 원본**: 다음 단계와 검토에는 md를 쓴다. HTML에만 있는 내용을 새로 넣지 않고, md를 고치면 HTML도 같이 고친다. 보완 모드에서는 둘 다 `-v2`로 만든다.
- **파일 하나로 완결**: CSS는 `<style>` 안에 넣는다. 외부 스크립트, 웹 폰트, 이미지 링크를 쓰지 않는다. 그림은 HTML·CSS나 인라인 SVG로 그린다.
- **구성**: 맨 위 제목·작성일 → "한눈에 보기" 카드 3~4개 → 핵심 그림 → 상세 표 → 출처.
- **모양**: 흰 배경, 진한 회색 글자, 강조색 1개(남색 `#2f4b7c`)와 상·중·하용 같은 색의 진하기 3단계. 글꼴은 시스템 기본 sans-serif. 본문 최대 너비 960px. 휴대폰에서 화면이 가로로 넘치지 않게 넓은 표는 표 안에서만 가로로 스크롤한다. A4로 인쇄해도 잘리지 않게 한다.
- **표시 유지**: 출처, "확인 필요", "가정" 표시는 HTML에도 그대로 남긴다(작은 배지).
- **참고 자료**에 시각화 기준(색, 양식)이 있으면 그것을 따른다.

이 스킬에서 그림으로 보여 줄 것:

- PEST 4칸 카드. 항목마다 기회·위협을 색 배지로 표시
- TAM·SAM·SOM 동심원(인라인 SVG)과 옆에 계산식 한 줄씩
- 시나리오(보수·기본·낙관)를 가로 막대로 비교
- 시장 구조는 이용자 → 결정자 → 지불자 흐름 화살표

## 마무리

파일을 만든 뒤 세 줄로 알린다.

1. 파일 이름 두 개: `market-landscape.md`(원본, 다음 단계에 주는 파일)와 `market-landscape.html`(보기용)
2. "다음 조사나 종합을 할 때 이 파일을 함께 주면 이어서 씁니다."
3. 확인 필요 항목 개수와 가장 민감한 가정 (검증할 때 먼저 볼 것)

- [ ] PEST 항목마다 기회·위협, 시점, 근거가 있다
- [ ] 규모에 Top-down과 Bottom-up이 모두 있고, Bottom-up 단계마다 출처나 "가정"이 있다
- [ ] 이용자 기준과 지불자 기준을 섞지 않았다
- [ ] 시나리오와 가장 민감한 가정이 있다
- [ ] 시장 구조를 깊이에 맞는 축 수만큼 채웠고, 수요 주기가 비어 있지 않다
- [ ] 원문을 열어 확인하지 못한 수치는 "확인 필요"로 표시했다
- [ ] 참고 자료가 있었다면 그 기준(용어, 주의점)을 지켰다

## 예시 (줄임)

입력: 주제 "출근일이 들쭉날쭉한 30대 1인 가구 직장인이 점심 메뉴 고르기가 피곤하고 점심값이 부담된다"

> 시장 정의: 수도권 사무실 직장인 대상 점심 식사 정기 구독 (배달앱 단건 주문·구내식당은 인접 시장)
> PEST: E1 외식 물가 상승 (기회, 지금) · E2 배달 수수료 인상 (위협, 지금) · S1 재택·출근 혼합 근무 확산 (기회, 곧)
> SAM (Bottom-up): 수도권 사무직 OO만 명 × 주 3회 이상 외식 OO% × 정기 배송 가능 지역 OO% × 연 OO원 = 연 OO억 원
> 가장 민감한 가정: 정기 배송 가능 지역 비율
> 수요 주기: 3·9월 높음 (인사 이동), 7~8월 낮음 (휴가)
