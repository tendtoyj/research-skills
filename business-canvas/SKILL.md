# business-canvas · 종합: 어떻게 돈을 버나

**새로 조사하지 않는다.** STP가 정한 "누구에게, 어떤 자리로"에 **"어떻게 돈을 버나"**를 붙인다. 아홉 칸을 채운 뒤 칸끼리 맞물리는지 점검하고, 무엇부터 확인하고 할지 정한다.

## 공통 규칙

- **참고 자료**: 작업 공간(대화 첨부, 프로젝트 파일, 지시문)에 맥락 파일이나 리서치 가이드가 있으면 먼저 읽는다. 그 안의 지불 구조, 규제, 주의점, 체크리스트를 이 스킬의 기준보다 우선한다.
- **근거 표시**: 모든 칸에 근거 파일과 항목을 괄호로 단다. 예: (STP 타겟), (시장 스캔 SAM), (경쟁사 가격), (소셜 리스닝 돈 신호). 근거가 없는 내용은 **"가정"**이라고 표시한다.
- **검토 결과 존중**: 팩트체크에서 틀렸다고 판정된 내용은 근거로 쓰지 않는다. 부분 일치나 확인 불가는 "확인 필요"를 단다.
- **결과는 파일로**: 대화창 답변이 아니라 **다운로드할 수 있는 파일 두 개**를 처음부터 함께 만든다. 원본 `business-canvas.md`와 보기용 `business-canvas.html`(아래 "보기용 HTML"). 사용자가 원하면 Word나 PDF도 준다. 사용자가 정한 파일명 규칙이 있으면 그것을 따른다.
- **메모리**: 본문은 저장하지 않는다. `[캔버스 완료] 가치 제안 1줄 / 수익원 1줄`만 남긴다.
- **분량**: A4 2~3쪽 안쪽.

## 모드

| 모드 | 언제 | 하는 일 |
|---|---|---|
| 새로 작성 | `business-canvas.md`가 없을 때 | 1~6단계를 처음부터 한다 |
| 보완 | 검토 결과(전문가 의견, 팩트체크)나 바뀐 조사 파일을 받았을 때 | 의견마다 반영 / 부분 반영 / 반영 안 함과 이유를 "검토 반영" 표에 적고 본문을 고친다. 파일명을 `business-canvas-v2.md`로 한다 |

## 1. 입력 확인

작업 공간(대화 첨부, 프로젝트 파일)에서 아래를 찾는다. 사용자가 정한 파일명 규칙이 있으면 그 이름으로 찾는다. `-v2`가 있으면 그것을 우선한다.

| 파일 | 없을 때 |
|---|---|
| STP (`stp.md`) | 멈추고 `/stp`를 먼저 하라고 안내한다 |
| 시장 스캔, 경쟁사, 소셜 리스닝 | 있는 것만 읽는다. 없는 조사에 기대는 칸은 "가정"으로 둔다 |
| 검토 결과 (`fact-check.md` 등) | 없어도 진행 |
| 이 아이디어를 고른 이유 | 사용자가 따로 알려 주면 고객 세그먼트 칸에 한 줄로 붙인다. 없으면 묻지 않는다 |

시작할 때 "읽은 파일 목록"과 "없는 조사"를 먼저 보여 주고 확인받는다.

## 2. STP에서 가져오는 칸

아래 두 칸은 새로 쓰지 않고 STP에서 가져온다. 캔버스에서 같은 내용을 다시 풀어 쓰지 않는다.

| 칸 | 가져올 것 |
|---|---|
| 고객 세그먼트 | STP의 타겟. 이용자와 결정자·지불자가 다르면 나눠 적는다 |
| 가치 제안 | STP의 포지셔닝 문장과 핵심 차별점 |

STP 이후에 받은 조사로 타겟이나 포지셔닝이 흔들리면, 고치지 말고 "STP와 달라진 점"에 적는다.

## 3. 새로 채우는 칸

이용자와 지불자가 다를 수 있다. 다르면 수익원과 채널을 **지불자 기준으로도** 따로 적는다.

| 칸 | 볼 것 | 주로 쓰는 근거 |
|---|---|---|
| 채널 | 고객이 우리를 알게 되고, 사고, 받는 길 | 소셜 리스닝 (정보를 얻는 곳), 경쟁사 (채널 활동, 채널 빈틈), 시장 스캔 (시장 구조의 채널) |
| 고객 관계 | 셀프 서비스, 커뮤니티, 1:1 지원, 자동화. 얼마나 자주 쓰게 되나 | 소셜 리스닝 (그만두는 이유), 경쟁사 (이용자 반응) |
| 수익원 | **누가, 무엇에, 얼마를, 어떤 방식으로** 내나. 시장 스캔의 가격 가정과 맞춘다 | 시장 스캔 (규모 계산의 가격), 경쟁사 (가격), 소셜 리스닝 (돈 신호, 결정의 계기) |
| 핵심 자원 | 있어야 하는 것: 데이터, 기술, 인력, 인허가, 브랜드 | 시장 스캔 P·T |
| 핵심 활동 | 꼭 해야 하는 일: 운영, 개발, 영업, 품질·규제 대응 | 시장 스캔 P, STP 페르소나 여정 |
| 핵심 파트너 | 함께해야 하는 곳: 공급, 유통, 제휴, 기관 | 경쟁사, 시장 스캔 |
| 비용 구조 | 큰 비용 순서: 개발, 운영, 마케팅, 인허가·인증 | 경쟁사, 시장 스캔 |

## 4. 칸끼리 맞물리는지 확인

다 채운 뒤 아래를 점검해 "맞물림 점검"에 적는다.

- 가치 제안을 고객 세그먼트가 실제로 원하나 (소셜 리스닝, STP 근거)
- 수익원에서 돈을 내는 사람이 고객 세그먼트에 있나
- 채널로 그 고객에게 실제로 닿을 수 있나
- 수익원의 가격으로 비용 구조를 대략이라도 감당하나
- 규제·인허가가 필요한 사업이면 핵심 활동과 비용 구조에 들어갔나

## 5. 가정 목록

캔버스에 들어간 가정마다 **틀리면 무너지는 칸**과 확인 방법(인터뷰, 원문 확인, 전문가 자문, 시험 판매)을 적는다. 가장 위험한 가정 1개를 짚는다.

## 6. 무엇부터 할까

캔버스와 가정 목록을 바탕으로 정한다.

- **제안 3~5개**: 무엇을, 왜(어느 칸·어느 가정에서 나왔나), 우선순위(상·중·하), 걸리는 시간(바로 1~2주 / 중기 1~3개월 / 장기 3~6개월). 우선순위 상 + 바로 할 수 있는 것부터 앞에 둔다.
- **다음 할 일 3개**: 가장 위험한 가정부터 확인하는 구체적인 일, 근거 파일, 잘됐는지 볼 지표.

## 보기용 HTML

md와 같은 내용을 **도식으로 바꿔** 한눈에 보이게 한 `business-canvas.html`을 처음부터 함께 만든다. md의 표를 HTML 표로 옮기는 것이 아니다. 분석 하나마다 아래 정한 도식 하나로 그린다.

- **md가 원본**: 다음 단계와 검토에는 md를 쓴다. HTML에만 있는 내용을 넣지 않고, md를 고치면 HTML도 고친다. 보완 모드에서는 둘 다 `-v2`로 만든다.
- **표는 맨 아래에만**: 위쪽 도식 부분에는 `<table>`을 쓰지 않는다. 도식은 CSS 격자(grid·flex)와 인라인 SVG로 그린다. 표는 맨 아래 "자세히 보기"(`<details>`로 접어 둠)에만 둔다.
- **파일 하나로 완결**: CSS는 `<style>` 안에 넣는다. 외부 스크립트·웹 폰트·이미지 링크를 쓰지 않는다. 흰 배경, 본문 최대 너비 960px, 휴대폰에서는 2열·4열 도식을 1열로 접는다. A4로 인쇄해도 잘리지 않게 한다.
- **근거 표시 유지**: 출처 번호, "확인 필요", "가정"을 도식 안에 작은 배지로 남긴다. "가정"인 칸은 점선 테두리로 그린다.
- **참고 자료**에 시각화 기준(색, 양식)이 있으면 그것을 따른다.

**이 화면의 질문**: 이 사업은 어떻게 돈을 벌고, 무엇이 틀리면 무너지나?

**도식** (위에서 아래 순서)

1. **한눈에 보기**: 카드 4장, 누구에게 / 무엇을 / 누가 돈을 내나 / 가장 위험한 가정(빨간 테두리).
2. **9칸 캔버스 판** (md "캔버스"): CSS 격자 10열 표준 배치. 위 줄 5칸 = 핵심 파트너 | 핵심 활동·핵심 자원(위아래) | 가치 제안 | 고객 관계·채널(위아래) | 고객 세그먼트. 아래 줄 2칸 = 비용 구조 | 수익원. 칸마다 제목과 짧은 줄 2~4개, 끝에 근거 배지(STP 타겟, 경쟁사 가격). 고객 세그먼트와 가치 제안 칸에는 "STP에서" 배지. "가정"인 줄은 점선 밑줄 + "가정" 배지. 이용자와 지불자가 다르면 고객 세그먼트·채널·수익원 칸 안을 "이용자 / 지불자" 두 칸으로 나눈다. 휴대폰에서는 9칸을 한 열로 접는다.
3. **위험 가정 연결** (md "가정 목록"): 판 바로 아래 빨간 경고 상자에 가장 위험한 가정. 이 가정이 틀리면 무너지는 칸들은 판 위에서 빨간 테두리와 같은 번호 표시(①). 나머지 가정도 번호(②, ③)를 붙여 해당 칸 모서리에 작은 표시.
4. **돈의 흐름** (md "수익원"·"비용 구조"): 가로 화살표 도식. 지불자 → (무엇에, 얼마를, 어떤 방식으로) → 우리 → 큰 비용 순서대로 비용 칩. 이용자와 지불자가 다르면 이용자는 위에 따로 그리고 점선으로 "쓰기만 함".
5. **맞물림 점검** (md "맞물림 점검"): 점검 줄 하나씩, 왼쪽에 ✓(초록) 또는 !(주황), 가운데 점검 내용, 오른쪽에 문제와 대응 한 줄.
6. **무엇부터 할까 격자** (md "무엇부터 할까"): 행 = 우선순위(상·중·하), 열 = 걸리는 시간(바로 1~2주 / 중기 1~3개월 / 장기 3~6개월). 제안을 해당 칸에 스티커 카드로 붙인다. "상 × 바로" 칸은 강조색 배경.
7. **다음 할 일 3단계** (md "다음 할 일"): 번호가 붙은 카드 3장 가로 배열, 카드마다 할 일, 근거 배지, 아래 "지표" 배지.
8. **STP와 달라진 점**: 있으면 노란 메모 상자 하나. 없으면 그리지 않는다.

**자세히 보기 (표)**: 캔버스 근거 표, 가정 목록 표, 검토 반영 표.

**가장 강조할 것**: 가장 위험한 가정과, 그것이 무너뜨리는 칸.

**조심할 것**
- 캔버스 칸에는 짧게만 쓰고 긴 설명과 근거는 "자세히 보기"로 보낸다.
- 9칸 배치를 바꾸지 않는다. 읽는 사람이 표준 캔버스로 알아볼 수 있어야 한다.

## 마무리

파일을 만든 뒤 알린다.

1. 파일 이름 두 개: `business-canvas.md`(원본, 다음 단계에 주는 파일)와 `business-canvas.html`(보기용)
2. "검토(전문가 의견 등)를 받은 뒤 결과를 주면 보완본을 만듭니다."
3. 가정 목록 개수와 그중 틀리면 가장 크게 무너지는 가정 1개

## 품질 체크리스트

- [ ] md와 html을 둘 다 만들었고, 두 파일의 내용이 같다
- [ ] html 위쪽에 표가 없고, "보기용 HTML"에 정한 도식이 모두 그려졌다
- [ ] 고객 세그먼트와 가치 제안이 STP와 같다 (다르면 "STP와 달라진 점"에 적었다)
- [ ] 아홉 칸 모두 근거가 있거나 "가정"으로 표시했다
- [ ] 수익원에 누가, 무엇에, 얼마를, 어떤 방식으로가 모두 있다
- [ ] 이용자와 지불자가 다른지 확인했다
- [ ] 맞물림 점검을 했다
- [ ] 가정마다 틀리면 무너지는 칸이 있다
- [ ] 다음 할 일이 가장 위험한 가정부터 확인한다
- [ ] 참고 자료가 있었다면 그 기준을 지켰다

## 예시 (줄임)

> 고객 세그먼트: 출근일이 들쭉날쭉한 30대 1인 가구 직장인 (이용자) / 일부는 회사 복지 담당자 (지불자)
> 수익원: 이용자 월 구독 OO원 (출근일만 배송), 기업 복지 계약 1인당 월 OO원 (경쟁사 가격 근거)
> 가장 위험한 가정: "회사가 복지비로 내 준다" → 틀리면 수익원·채널·고객 관계 세 칸이 무너진다
> 다음 할 일: 복지 담당자 3명 인터뷰 (지표: 도입 검토 의향 2명 이상)
