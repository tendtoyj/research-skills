# competitor-analysis · 경쟁사 분석 (3C / SWOT)

주제와 같은 문제를 푸는 서비스, 그리고 사람들이 지금 **대신** 쓰는 방법을 찾아 비교한다. 3C로 상황을 보고, SWOT으로 우리 아이디어의 자리를 정리하고, 아무도 차지하지 않은 빈틈을 찾는다.

## 공통 규칙

- **참고 자료**: 작업 공간(대화 첨부, 프로젝트 파일, 지시문)에 맥락 파일이나 리서치 가이드가 있으면 먼저 읽는다. 그 안의 용어 정의, 데이터 소스, 확인해야 할 항목(인허가, 인증 등), 체크리스트를 이 스킬의 기준보다 우선한다.
- **출처**: 회사 정보, 가격, 인허가·인증, 투자 정보마다 [출처, 확인일, 링크]를 붙인다. 검색 결과 요약만 보고 쓰지 않고 공식 페이지나 앱 마켓을 열어 확인한다. 찾지 못하면 "확인 필요".
- **최신성**: 가격과 기능은 자주 바뀐다. 확인일을 꼭 적는다. 서비스 종료 여부도 확인한다.
- **결과는 파일로**: 다운로드할 수 있는 파일. 기본 `.md`, 사용자가 원하면 Word나 PDF. 파일명은 `competitive-intel.md`, 사용자가 정한 파일명 규칙이 있으면 그것을 따른다.
- **메모리**: 본문은 저장하지 않는다. `[경쟁사 완료] 직접 N · 간접 N · 대체재 N / 핵심 빈틈 1줄`만 남긴다.
- **분량**: A4 2~3쪽 안쪽.

## 먼저 읽을 것

작업 공간의 조사 파일을 모두 읽는다. `market-landscape.md`가 있으면 여기서 가져온다.

| 가져올 것 | 쓰는 곳 |
|---|---|
| 시장 정의 | 검색어의 중심 |
| 인접 시장 | 간접 경쟁사를 찾을 곳 |
| 시장 구조의 가격대·채널 | 경쟁사를 나누는 틀, 경쟁사를 찾을 곳 |
| PEST 항목 | SWOT의 기회·위협 근거 |

`customer-voice.md`가 있으면 "지금 대신 하는 것"을 대체재 후보로 쓴다.

## 1. 입력 확인

- 리서치 주제 정의와 시장 정의: 지시문이나 메모리에 있으면 확인만 한다. 없으면 묻는다. 아예 없으면 `/research-topic`을 먼저 하자고 안내한다.
- 사용자가 이미 아는 경쟁 서비스가 있으면 받는다. 출발점으로 넣고 검색으로 검증하고 넓힌다.
- 우리 아이디어를 한 문장으로 받는다. 없으면 주제에서 가정하고 "가정"으로 표시한다.
- 조사 깊이: 가볍게 / 보통 / 깊게 (기본: 보통)

## 조사 깊이

| 깊이 | 단계당 웹 검색 | 원문 열람 | 찾을 수 |
|---|---|---|---|
| 가볍게 | 1~2회 | 0~1건 | 직접 2~3 · 간접 1~2 · 대체재 1~2 |
| 보통 | 3~4회 | 2~3건 | 직접 3~5 · 간접 2~3 · 대체재 2~3 |
| 깊게 | 5~6회 | 4~6건 | 직접 5~8 · 간접 2~3 · 대체재 2~3 |

## 2. 경쟁 범위 찾기

먼저 검색 범위를 정한다: 시장 정의, 지역, 찾을 채널(앱 마켓, 쇼핑몰, 기업 판매, 오프라인). 그다음 세 겹으로 찾는다. **대체재**가 가장 강한 경쟁자인 경우가 많다.

| 구분 | 뜻 | 예 (점심 정기 구독이라면) |
|---|---|---|
| 직접 경쟁 | 같은 사람의 같은 문제를 같은 방식으로 푸는 서비스 | 도시락 정기 배송 |
| 간접 경쟁 | 같은 문제를 다른 방식으로 풀거나 인접 시장에서 넘어오는 서비스 | 배달앱 단체 주문, 구내식당 위탁 |
| 대체재 | 지금 사람들이 대신 하는 것 | 편의점 도시락, 집에서 싸 오기, 점심 거르기 |

국내 서비스를 먼저, 해외는 대표 사례만 넣는다. 경쟁사마다 왜 그 구분으로 봤는지 한 줄 이유를 단다.

## 3. 경쟁사별로 볼 것

| 항목 | 내용 |
|---|---|
| 대상 | 누구를 위한 서비스인가 (이용자 / 결정자 / 지불자) |
| 포지셔닝 | 스스로를 어떻게 소개하나 (대표 문구, 첫 화면 제목) |
| 핵심 가치 제안 | 강조하는 이점 2~3개 |
| 핵심 기능 | 대표 기능 3개 |
| 수익 모델·가격 | 무료, 부분 유료, 구독, 일회 구매, 기업 계약 등과 대표 요금 |
| 지불자 | 누가 돈을 내는가 |
| 인허가·인증 | 해당 시장에서 필요한 경우만. 확인 못 하면 "확인 필요" |
| 근거 | 연구, 수상, 도입 사례 등 공개된 것 |
| 이용자 반응 | 앱 리뷰·커뮤니티의 반복되는 불만과 칭찬을 **요약**으로만. 원문 인용 금지 |
| 규모 신호 | 다운로드 수, 이용자 수, 투자 유치, 제휴 (출처와 함께) |

보통·깊게일 때는 핵심 경쟁사 2~3곳의 **첫 화면과 가격 페이지를 직접 열어** 대표 문구와 요금 구성을 확인한다. 검색 요약과 원문이 다르면 원문을 따른다.

## 4. 채널 활동

경쟁사가 어디서 고객을 만나는지 본다. 채널마다 강함 / 보통 / 약함 / 없음.

- 콘텐츠 (블로그, 유튜브, 팟캐스트)
- 소셜 미디어 (어느 플랫폼)
- 검색 광고, 검색 노출
- 이메일, 뉴스레터
- 커뮤니티, 오프라인, 제휴

## 5. 3C

| C | 볼 것 |
|---|---|
| Customer 고객 | 고객이 기존 방법에서 무엇을 불편해하는가 (리뷰·커뮤니티 요약, 시장 스캔의 S 항목, 소셜 리스닝) |
| Competitor 경쟁 | 경쟁사들이 공통으로 잘하는 것과 공통으로 놓치는 것 |
| Company 우리 | 우리 아이디어가 가진 것과 없는 것 (역량, 접근 가능한 채널 등) |

## 6. SWOT

우리 아이디어 기준으로 쓴다. S·W는 우리 안, O·T는 바깥 환경이다. O·T는 시장 스캔 파일의 PEST 번호를 근거로 단다. 시장 스캔 파일이 없으면 "가정"으로 표시한다.

## 7. 빈틈과 직접 써 볼 것

- **빈틈** 세 가지를 각각 찾는다.
  - 채널 빈틈: 대부분이 소홀한 채널
  - 포지셔닝 빈틈: 아무도 노리지 않는 대상이나 자리
  - 메시지 빈틈: 경쟁사들이 말하지 않는 고객의 불편
- **직접 써 볼 것**: 벤치마킹은 직접 써 보는 게 핵심이다. 사용자가 실제로 써 볼 서비스 2개와, 써 보면서 볼 체크포인트 3개를 제안한다.

## 마무리

파일을 만든 뒤 세 줄로 알린다.

1. 파일 이름
2. "다음 조사나 종합을 할 때 이 파일을 함께 주면 이어서 씁니다."
3. 가격·인허가처럼 "확인 필요"로 남은 항목 개수

## 품질 체크리스트

- [ ] 직접·간접 경쟁사와 대체재가 모두 있다 ("아무것도 안 함"도 검토했다)
- [ ] 경쟁사마다 구분한 이유, 링크, 확인일이 있다
- [ ] 가격은 공식 페이지나 앱 마켓에서 확인했거나 "확인 필요"로 표시했다
- [ ] 종료된 서비스를 현재 경쟁사로 쓰지 않았다
- [ ] 이용자 반응을 원문 인용 없이 요약했다
- [ ] 빈틈이 세 가지(채널, 포지셔닝, 메시지) 모두 채워져 있다
- [ ] SWOT의 기회·위협에 근거 번호가 있거나 "가정"으로 표시했다
- [ ] 참고 자료가 있었다면 그 기준을 지켰다

## 예시 (줄임)

> 직접: A도시락 정기 배송 (주 5회 고정, 월 OO원, 확인일 YYYY-MM-DD)
> 간접: 배달앱 단체 주문 / 대체재: 편의점 도시락, 점심 거르기
> 포지셔닝 빈틈: "출근하는 날만 받는 유연한 구독" 자리를 차지한 곳이 없음
> 메시지 빈틈: 경쟁사는 "메뉴 다양성"을 강조하지만 고객 불편은 "고르는 피로"

## 하지 않는 것

- 경쟁사 웹사이트 대량 수집, 리뷰 원문 수집
- 시장 규모 계산 → `market-scanner`
- 사람들의 목소리를 넓게 모으기 → `customer-voice`
- 타겟과 포지셔닝 결정 → `stp`
