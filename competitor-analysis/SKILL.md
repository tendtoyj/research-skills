# competitor-analysis · 경쟁사 분석 (3C / SWOT)

시장조사 3단계다. 주제와 같은 문제를 푸는 서비스, 그리고 사람들이 지금 대신 쓰는 방법을 찾아 비교한다. 3C로 상황을 보고, SWOT으로 우리 아이디어의 자리를 정리한다.

## 공통 규칙

- **맥락 파일**: 시작 전에 프로젝트 파일의 `healthcare-context.md`를 읽고 그 기준을 따른다. 파일이 없으면 올려 달라고 알리고, 없이 진행하면 결과 맨 위에 "맥락 파일 없이 작성"이라고 적는다.
- **출처**: 회사 정보, 가격, 허가 여부, 투자 정보마다 [출처, 확인일, 링크]를 붙인다. 찾지 못하면 "확인 필요".
- **결과는 파일로**: 다운로드할 수 있는 파일로 만든다. 기본 `.md`, 사용자가 원하면 Word나 PDF. 파일명은 `competitive-intel.md`이다. 프로젝트 지시문에 파일명 규칙이 있으면 그 규칙을 따른다.
- **메모리**: 본문은 저장하지 않는다. `[경쟁사 완료] 직접 N개 · 간접 N개 · 핵심 빈틈 1줄`만 남긴다.
- **분량**: A4 2~3쪽 안쪽.

## 1. 입력 확인

- 주제: 메모리에 있으면 확인만 한다. 없으면 묻는다.
- 프로젝트 파일에 트렌드·시장규모 파일(기본 이름 또는 프로젝트 지시문 규칙에 따른 이름)이 있으면 읽고 시장 정의를 맞춘다.
- 사용자가 이미 아는 경쟁 서비스가 있으면 받는다.
- 우리 아이디어를 한 문장으로 받는다. 없으면 주제에서 가정하고 가정이라고 표시한다.

## 2. 경쟁 범위 찾기

세 겹으로 찾는다. 헬스케어에서는 **대체재**가 가장 강한 경쟁자인 경우가 많다.

| 구분 | 뜻 | 예 (당뇨 기록 앱이라면) |
|---|---|---|
| 직접 경쟁 | 같은 사람의 같은 문제를 같은 방식으로 푸는 서비스 | 혈당 기록 앱 |
| 간접 경쟁 | 같은 문제를 다른 방식으로 푸는 서비스 | 연속혈당측정기 전용 앱, 병원 앱, 범용 건강 앱 |
| 대체재 | 지금 사람들이 대신 하는 것 | 종이 수첩, 메모장, 카톡으로 사진 보내기, 아무것도 안 하기 |

직접 3~5개, 간접 2~3개, 대체재 2~3개를 찾는다. 국내 서비스를 먼저, 해외는 대표 사례만 넣는다.

## 3. 경쟁사별로 볼 것

| 항목 | 내용 |
|---|---|
| 대상 | 누구를 위한 서비스인가 (이용자 / 결정자 / 지불자) |
| 핵심 기능 | 대표 기능 3개 |
| 수익 모델·가격 | 무료, 구독, 기관 판매, 보험 연계 등 |
| 지불자 | 누가 돈을 내는가 |
| 의료/웰니스 | 의료기기 허가·인증 여부. 확인 못 하면 "확인 필요" |
| 근거 | 임상연구, 논문, 수상, 도입 병원 등 공개된 것 |
| 이용자 반응 | 앱 리뷰·커뮤니티의 반복되는 불만과 칭찬을 **요약**으로만. 원문 인용 금지 |
| 규모 신호 | 다운로드 수, 투자 유치, 제휴 (출처와 함께) |

## 4. 3C

| C | 볼 것 |
|---|---|
| Customer 고객 | 고객이 기존 방법에서 무엇을 불편해하는가 (리뷰·커뮤니티 요약, 트렌드 파일의 S 항목) |
| Competitor 경쟁 | 경쟁사들이 공통으로 잘하는 것과 공통으로 놓치는 것 |
| Company 우리 | 우리 아이디어가 가진 것과 없는 것 (팀의 역량, 접근 가능한 채널 등도 포함) |

## 5. SWOT

우리 아이디어 기준으로 쓴다. S·W는 우리 내부, O·T는 바깥 환경이다. O·T는 트렌드 파일의 PEST 항목 번호를 근거로 단다.

## 6. 빈틈과 직접 써볼 것

- **빈틈**: 경쟁사들이 공통으로 놓친 고객 문제, 아무도 노리지 않는 대상, 아무도 쓰지 않는 채널. 3개 이내.
- **직접 써볼 것**: 벤치마킹은 직접 써보는 것이 핵심이다. 사용자가 실제로 설치해서 확인할 서비스 2개와, 써보면서 볼 체크포인트 3개를 제안한다.
