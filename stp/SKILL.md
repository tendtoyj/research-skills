# stp · 종합: 누구에게, 어떤 자리로

**새로 조사하지 않는다.** 조사 파일을 서로 맞대어, 파일 하나로는 보이지 않는 **연결**을 찾고 "누구에게, 어떤 자리로" 갈지 정한다. 파일 하나의 내용을 되풀이한 것은 종합이 아니다. 결과는 `business-canvas`가 이어서 읽는다.

## 공통 규칙

- **참고 자료**: 작업 공간(대화 첨부, 프로젝트 파일, 지시문)에 맥락 파일이나 리서치 가이드가 있으면 먼저 읽는다. 그 안의 세분화 기준, 주의점, 체크리스트를 이 스킬의 기준보다 우선한다.
- **근거 표시**: 모든 판단에 근거 파일과 항목을 괄호로 단다. 예: (시장 스캔 S2), (시장 스캔 SAM), (경쟁사 빈틈-메시지), (소셜 리스닝 불편 2). 조사 파일에 근거가 없는 내용은 **"가정"**이라고 표시한다.
- **검토 결과 존중**: 팩트체크에서 틀렸다고 판정된 내용은 근거로 쓰지 않는다. 부분 일치나 확인 불가는 "확인 필요"를 단다.
- **결과는 파일로**: 대화창 답변이 아니라 **다운로드할 수 있는 파일 두 개**를 처음부터 함께 만든다. 원본 `stp.md`와 보기용 `stp.html`(아래 "보기용 HTML"). 사용자가 원하면 Word나 PDF도 준다. 사용자가 정한 파일명 규칙이 있으면 그것을 따른다.
- **메모리**: 본문은 저장하지 않는다. `[STP 완료] 타겟 1줄 / 포지셔닝 문장`만 남긴다.
- **분량**: A4 2~3쪽 안쪽. 맨 위 '한눈에 보기'만 읽어도 결론을 알 수 있어야 한다.

## 모드

| 모드 | 언제 | 하는 일 |
|---|---|---|
| 새로 종합 | `stp.md`가 없을 때 | 1~6단계를 처음부터 한다 |
| 보완 | 조사 파일이 바뀌었거나 검토 결과(팩트체크, 의견)를 받았을 때 | 처음부터 다시 쓰지 않고 바뀐 부분만 고친다. 틀렸다고 판정된 수치는 근거에서 빼고, 부분 일치·확인 불가는 "확인 필요"를 단다. 의견마다 반영 / 부분 반영 / 반영 안 함과 이유를 파일 끝 "보완 내역" 표에 적는다. 파일명을 `stp-v2.md`로 한다 |

## 1. 조사 파일 읽고 점검하기

작업 공간(대화 첨부, 프로젝트 파일)에서 아래를 찾는다. 사용자가 정한 파일명 규칙이 있으면 그 이름으로 찾는다. `-v2`(보완본)가 있으면 그것을 우선한다.

| 파일 | 가져올 것 | 없을 때 |
|---|---|---|
| 시장 스캔 (`market-landscape.md`) | 시장 정의, PEST(기회·위협), 규모, 시장 구조 | 시장 정의를 사용자와 먼저 맞춘다. 규모와 외부 제약 판단은 "가정" |
| 경쟁사 (`competitive-intel.md`) | 경쟁 지도, 포지셔닝 비교, 채널, 빈틈 | 경쟁 강도와 포지셔닝은 "가정". 대체재를 놓고 배치한다 |
| 소셜 리스닝 (`customer-voice.md`) | 사용 장면, 불편과 심각도, 대신 하는 것, 정보를 얻는 곳, 가설 | 문제의 크기와 페르소나의 불편은 "가정" |
| 검토 결과 (`fact-check.md` 등) | 틀린 것, 확인 필요한 것 | 없어도 진행 |

- 조사 파일이 **하나도 없으면** 멈추고 먼저 조사를 하라고 안내한다.
- 영역마다 충분 / 보통 / 부족을 매겨 "읽은 파일 점검"으로 먼저 보여 주고, 빠진 게 있는지 확인받는다.

## 2. 교차 분석

조사 파일 두 개 이상을 맞대어 연결을 찾는다. 해당 파일이 없는 분석은 억지로 채우지 않고 "자료 부족"으로 표시한다. 튼튼한 분석 2개와 "자료 부족" 1개가, 약한 분석 3개보다 낫다.

| 분석 | 맞대는 것 | 찾는 것 |
|---|---|---|
| 기회 | 시장 스캔의 기회 트렌드 × 경쟁사 빈틈 | 흐름이 오는데 아무도 차지하지 않은 자리 (급함, 매력을 상·중·하로) |
| 메시지 | 소셜 리스닝의 심각한 불편 × 경쟁사가 말하지 않는 것 | 우리가 가질 수 있는 메시지와, 그 불편을 부르는 사람들의 말 |
| 진입 | 시장 구조(가격대, 채널) × 세분화 그룹 | 어느 그룹에, 어느 가격대와 채널로 들어가기 쉬운가 |

## 3. 세분화 (Segmentation)

시장을 2~4개 그룹으로 나눈다. 나이·성별만으로 나누지 말고 **상황과 행동**으로 나눈다.

- 문제를 겪는 단계 (막 알아차림 / 해결책을 찾는 중 / 이미 무언가를 쓰는 중 / 포기함)
- 지금 대신 쓰는 방법
- 디지털 이용 정도
- 지불 능력과 지불 주체 (본인 / 회사·기관 / 가족)
- 정보를 찾는 곳

소셜 리스닝 파일이 있으면 거기서 나온 사용 장면을 세분화 기준으로 우선 검토한다. 참고 자료에 그 분야에서 의미 있는 세분화 기준이 있으면 그것을 쓴다. 그룹마다 규모, 핵심 불편, 닿기 쉬움(쉬움·보통·어려움), 지불 의향(높음·보통·낮음)을 적고, 근거가 없으면 "가정"으로 둔다.

## 4. 타겟팅 (Targeting)

그룹을 아래 기준으로 비교해 하나를 고른다. 상·중·하로 매기고 이유를 한 줄씩 단다. 근거 파일이 없는 기준은 칸에 "가정"을 함께 적는다.

| 기준 | 근거 파일 |
|---|---|
| 규모 | 시장 스캔 (SAM, 시장 구조의 고객군) |
| 문제의 크기 | 소셜 리스닝 (불편의 심각도·빈도), 시장 스캔 S |
| 경쟁 강도 | 경쟁사, 교차 분석 '진입' |
| 닿을 수 있는가 (채널) | 소셜 리스닝 (정보를 얻는 곳), 경쟁사 (채널 빈틈) |
| 지불 의향과 지불자 | 소셜 리스닝 (돈 신호), 시장 스캔 (이용자 / 지불자) |
| 외부 제약 | 시장 스캔 P (규제·제도) |

처음 떠올린 고객과 비교 결과 고른 고객이 다르면, 그 차이를 "조사로 바뀐 점"에 적는다.

## 5. 포지셔닝 (Positioning)

- **포지셔닝 맵**: 고객이 중요하게 여기는 축 2개를 고른다(경쟁사 또는 소셜 리스닝 근거). 경쟁사와 우리를 표로 배치한다(축1 낮음·높음 × 축2 낮음·높음). 경쟁사 파일이 없으면 사람들이 지금 대신 쓰는 방법(대체재)을 놓고 배치하고 "가정"으로 표시한다.
- **포지셔닝 문장**: "[타겟]에게 [우리 서비스]는 [경쟁 대안]과 달리 [핵심 차별점]을 주는 [카테고리]다."
- 차별점이 교차 분석의 '기회'나 '메시지'와 이어지는지 확인한다. 이어지지 않으면 이유를 적는다.

## 6. 페르소나 1명

타겟 그룹을 대표하는 가상 인물 한 명을 만든다. 실존 인물이나 커뮤니티 글쓴이를 본뜨지 않는다.

- 이름 · 나이 · 상황 (한 줄)
- 목표
- 불편함 (근거 파일 표시)
- 여정: 문제를 **알아차리는** 순간 → **비교**할 때 보는 것 → **결정**하게 만드는 것 → **써 본 뒤** 그만두거나 추천하는 이유. 근거가 없는 단계는 "가정"
- 정보를 얻는 곳, 지금 대신 쓰는 방법

## 보기용 HTML

md와 같은 내용을 한눈에 보이게 정리한 `stp.html`을 처음부터 함께 만든다.

- **md가 원본**: 다음 단계와 검토에는 md를 쓴다. HTML에만 있는 내용을 넣지 않고, md를 고치면 HTML도 고친다. 보완 모드에서는 둘 다 `-v2`로 만든다.
- **파일 하나로 완결**: CSS는 `<style>` 안에, 그림은 HTML·CSS나 인라인 SVG로. 외부 스크립트·웹 폰트·이미지 링크는 쓰지 않는다. 흰 배경에 강조색 하나, 휴대폰과 A4 인쇄에서 잘리지 않게. 참고 자료에 시각화 기준이 있으면 그것을 따른다.
- **근거 표시 유지**: 출처, "확인 필요", "가정" 표시를 HTML에도 작은 배지로 남긴다.

**이 화면의 질문**: 누구를 고르고, 어떤 자리를 잡나?

**화면 순서**

1. 맨 위 작은 줄: 읽은 파일과 안 한 조사
2. 한눈에 보기: 타겟과 포지셔닝 문장을 크게
3. 세그먼트 카드. 고른 타겟은 강조색 테두리
4. 타겟팅 기준표. 상·중·하를 색 3단계로
5. 포지셔닝 맵: 우리와 경쟁사를 점으로 찍은 인라인 SVG
6. 페르소나 카드와 여정 4단계 가로 흐름
7. 교차 분석, 가정 목록

**가장 강조할 것**: 포지셔닝 문장

**조심할 것**

- 경쟁사 점은 경쟁사 조사 파일 근거로만 찍는다. 파일이 없으면 맵에 "가정" 배지를 단다
- 페르소나에 사진이나 일러스트를 넣지 않는다. 이름과 특징은 글자로만
- 안 한 조사를 감추지 않는다

## 마무리

파일을 만든 뒤 알린다.

1. 파일 이름 두 개: `stp.md`(원본, 다음 단계에 주는 파일)와 `stp.html`(보기용)
2. "검증(팩트체크)을 받은 뒤 결과를 주면 보완본을 만듭니다."
3. 가정 목록 개수와 안 한 조사

## 좋은 종합과 나쁜 종합

- **좋은 종합**: 둘 이상의 파일을 잇는다 → 타겟과 자리를 구체적으로 가리킨다 → 실제 수치와 사람들의 말을 쓴다 → 모자란 자료를 인정한다.
- **나쁜 종합**: 파일 하나의 내용을 다시 쓴다, 근거 없는 주장을 한다, "2030 전체" 같은 넓은 타겟을 고른다.
- 연결이 없으면 만들어 내지 않는다.

## 품질 체크리스트

- [ ] md와 html을 둘 다 만들었고, 두 파일의 내용이 같다
- [ ] '한눈에 보기'만 읽어도 타겟과 포지셔닝을 알 수 있다
- [ ] 읽은 파일 점검이 있다
- [ ] 교차 분석마다 두 파일 이상을 근거로 썼거나 "자료 부족"으로 표시했다
- [ ] 세분화가 상황·행동 기준이고, 그룹끼리 겹치지 않는다
- [ ] 타겟 선택 이유가 기준별로 있다
- [ ] 포지셔닝 문장의 차별점이 교차 분석과 이어진다
- [ ] 페르소나가 실존 인물을 본뜨지 않았다
- [ ] 검토에서 틀렸다고 판정된 내용을 근거로 쓰지 않았다
- [ ] 참고 자료가 있었다면 그 기준을 지켰다

## 예시 (줄임)

> 기회: 외식 물가 상승 (시장 스캔 E1) × "출근일만 받는 구독" 자리 빔 (경쟁사 빈틈-포지셔닝) → 급함 상, 매력 중
> 메시지: "메뉴 고르는 피로" (소셜 리스닝 불편 1, 높음) × 경쟁사는 "메뉴 다양성"만 말함 → "고르지 않아도 되는 점심"
> 타겟: 출근일이 들쭉날쭉한 30대 1인 가구 직장인
> 포지셔닝 문장: "출근일이 들쭉날쭉한 30대 직장인에게 OO는 매일 오는 정기 배송과 달리 출근하는 날만 알아서 오는 점심 구독이다."

## 하지 않는 것

- 새로운 웹 조사 (근거가 부족하면 "가정"으로 표시하고 어떤 조사가 필요한지만 적는다)
- 수익 구조, 채널 설계, 비용 → `business-canvas`
